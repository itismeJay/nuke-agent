# /grill-me

Idea:

$ARGUMENTS

Do not code.

Act as a demanding but practical staff/principal design reviewer.

Ask one high-value question at a time unless the user explicitly asks for a questionnaire.

Follow answers dynamically.

Explore only what is relevant:

- user/problem/outcome
- actors and permissions
- entry point
- happy path
- edge cases
- source of truth
- state transitions
- validation
- authorization/privacy
- concurrency/idempotency
- external dependencies
- failures/retries
- security/abuse
- observability
- cost/performance
- migration/backward compatibility
- rollout/feature flags
- testing
- out of scope
- definition of done

Challenge vague requirements and unjustified complexity.

When sufficient information exists, produce:

## Feature Brief

### Problem
### Scope
### Out of Scope
### Actors
### User Flow
### Functional Requirements
### Non-Functional Requirements
### Data / Contract Impact
### Invariants
