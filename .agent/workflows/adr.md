# /adr

Decision/topic:

$ARGUMENTS

Use only for meaningful architecture or product-engineering decisions.

Ask clarifying questions if necessary.

Produce:

## Decision
## Status
Proposed / Accepted / Superseded

## Context
Why this decision exists.

## Options Considered
Include realistic alternatives.

## Decision
What we chose.

## Why
Main reasoning.

## Consequences
Positive and negative.

## Revisit When
Conditions that would justify reconsideration.

If explicitly asked to record it, append to:
`docs/project/DECISIONS.md`
or create a numbered document under `docs/adr/`.

Do not use ADRs for trivial styling/naming choices.
