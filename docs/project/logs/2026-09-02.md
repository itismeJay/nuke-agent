### What changed — schema

- **New migration `20260902101500_tenant_scoped_child_fks`** (applied to
  `lemtlbepgrkltkmjbmqy`, verified, advisors clean):
  - `profile` + `resume_version` get `UNIQUE (id, user_id)`.
  - `experience`, `project`, `skill`, `education`, `master_resume` FKs →
    `(profile_id, user_id) REFERENCES profile (id, user_id) ON DELETE CASCADE`.
  - `application` FK → `(resume_version_id, user_id) REFERENCES resume_version
    (id, user_id) ON DELETE CASCADE`.
  - Closes the review finding "cross-user parent/child FK vulnerability" (R-001).
    RLS checked `user_id` on the row but not that `profile_id` /
    `resume_version_id` belonged to the same user.
  - Verified live: matching `(profile_id, user_id)` inserts; a mismatched
    `user_id` raises `foreign_key_violation`.
- Renamed the vendored `20260901120000_idempotent_account_initialization.sql` →
  `20260901093525_…` to match the applied version in
  `supabase_migrations.schema_migrations`. Updated `supabase/README.md`.
- Regenerated `lib/supabase/database.types.ts` (composite `referencedColumns`).

### What changed — auth code (R-002)

- `updatePassword` now calls `supabase.auth.signOut({ scope: "others" })` after a
  successful reset — an attacker's session dies with the old password.
- `?error=` is passed as a **code** (`oauth_start` / `oauth_failed` /
  `link_invalid` / `link_expired`) and mapped to fixed copy by
  `authErrorMessage` (`lib/auth/errors.ts`). The sign-in page no longer reflects
  arbitrary query text into its error banner.
- `app/(app)/layout.tsx`: `ensureAccountInitialized` now runs **only when the
  profile row is missing** — normal navigation is 1 read, 0 writes (was 2 writes
  per request).
- Redirect validation was already centralized in `lib/auth/redirect.ts`
  (`safeRelativePath` / `safeRedirect`, unit-tested) by the prior commit — kept,
  removed a duplicate helper.

### Product direction re-baselined (D-014…D-020)

Reviewed a full updated architecture/product brief. Key decisions recorded:

- **D-014** — Manual Apply is the first MVP (Phases 0–8); Assisted / Autonomous
  are layered after. Three modes table.
- **D-015** — Browserbase stays, scoped to user-initiated Assisted Apply,
  Greenhouse + Lever first.
- **D-016** — Inngest is the durable-workflow system; not a bus for CRUD;
  installed in Phase 3.
- **D-017** — shared Job entity, per-user state separate.
- **D-018** — cross-tenant relational integrity enforced by composite FKs, not
  RLS alone.
- **D-019** — deployment is GitHub Actions → Vercel; no AWS. Old "Phase 17 —
  Production CI/CD on AWS" removed from the plan.
- **D-020** — Career Profile does not require a resume; onboarding offers
  upload-or-manual, no non-closable gate.
