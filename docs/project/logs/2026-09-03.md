### Security / authorization

- Upload: browser MIME/extension not trusted — `%PDF-` magic bytes sniffed;
  10 MB cap; filename sanitized (path stripped, char allow-list, `.pdf` forced);
  Storage object key is a server UUID, never the filename; encrypted PDFs
  rejected.
- Storage: private bucket; owner-folder-scoped policies; no UPDATE/DELETE (D-003);
  "view original" via 60 s signed URL, `Content-Disposition: attachment`.
- `SUPABASE_SERVICE_ROLE_KEY` enters the project for the first time — only the
  Inngest parser uses it, every query scoped to the event's `user_id`,
  `master_resume` ownership re-checked. Still **unset** in `.env.local`.
- Résumé text treated as untrusted: system-prompt isolation + structured output
  + Zod re-validation + **the review gate** — nothing the model produces reaches
  the profile without a human Accept.
- Merge runs under the user's RLS client; `resume_import_item.field` checked
  against a per-entity allow-list before any dynamic column write.
- `/api/inngest` unauthenticated by design, signature-verified in deployed envs.
