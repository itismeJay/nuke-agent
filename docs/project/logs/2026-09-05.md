## Résumé extraction provider swapped to Gemini (temporary)

- **Phase:** Phase 3 — Master Resume Import (still CODE COMPLETE, not runtime-verified).
- **What changed:** `lib/resume/parse-pipeline.ts` now imports `extractResumeData`
  from new `lib/ai/gemini.ts` instead of `lib/ai/claude.ts` — Anthropic billing
  isn't set up yet. `gemini.ts` shares `resume-schema.ts` / `prompts.ts` with the
  Claude path so the two can't drift; `claude.ts` is left in place, untouched, as
  the revert path. Model `gemini-3.5-flash-lite` (only Flash-tier model available
  on this key's free-tier quota as of 2026-09-05; every Pro-tier model returned
  `RESOURCE_EXHAUSTED`). Originally tried `gemini-3.8-flash`, switched same day
  after its 20-requests/day free quota was exhausted by testing.
- **Database/migrations:** none.
- **Security/authorization:** unchanged — same invariant either provider:
  extraction only transcribes, output never reaches trusted profile data without
  human review in `/resumes/import/[id]`. Gemini's `responseJsonSchema` lacks a
  `"null"` type/`nullable` keyword (unlike Anthropic's `zodOutputFormat`), so
  `gemini.ts` sanitizes `resumeExtractionSchema`'s generated JSON Schema to
  Gemini's accepted keyword subset before sending it; `resumeExtractionSchema
  .safeParse` still re-validates the response exactly as the Anthropic path does.
- **Tests/verification:** no new automated tests (extraction call itself is
  `server-only`, TD-008); existing `resume-schema` unit tests still cover both
  paths' shared validation.
- **Decisions:** D-025 (Gemini swap, temporary) — reaffirms D-001/D-022 (no
  multi-provider abstraction; switching stays a one-line import).
- **Known issues:** Phase 3 runtime E2E is still unverified — Inngest has never
  run against this pipeline (local or cloud). `GEMINI_API_KEY` and remote
  `SUPABASE_SERVICE_ROLE_KEY` are set in `.env.local`; Inngest is the only
  remaining blocker.
- **Next:** stand up an Inngest Cloud project (not just local `inngest-cli dev`)
  — app id `nook`, `INNGEST_EVENT_KEY` / `INNGEST_SIGNING_KEY` per environment,
  synced to a deployed `/api/inngest` — then run a real résumé through
  parse → review → merge before Phase 3 human acceptance.
